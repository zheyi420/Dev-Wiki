1. 使用 github 开源的 [v2ray](https://github.com/v2fly/v2ray-core)；
   1. 开源的第三方图形客户端 [v2rayN](https://github.com/2dust/v2rayN) 也行吧，不知道有没有问题；
   2. 使用别人提供的 v2ray，有可能加入了安装证书的代码；
2. 设置非全局模式，国内能访问的站点，就不使用代理；
   1. 不在 http 网站输入保密信息；
      > HTTP 访问的网站会被窃取，不过现在的网站大多数是 HTTPS 访问，HTTPS 访问的网站如果没有装根证书（一般很难装上，因为换了节点根证书也没用了）则无需担心，收费节点和免费节点安全性是一样的
   2. 不使用全局好麻烦，所以尽量配置好路由等其他的吧；
3. **千万不能安装第三方根证书**，不然 https 被劫持了也不知道；
4. 不使用自带节点的第三方软件，某某加速器，某某VPN等此类软件可能会给你自动安装证书；
5. 经常检查证书链，保障数据安全；

证书查看

1. 键盘 window + R 运行输入 certmgr.msc；
   1. 查看：受信任的根证书颁发机构 → 证书

其他

1. 我们现在使用的各种协议，比如 ss/ssr/vmess/ 等这些的本质其实都是基于 socks5 代理协议的二次混淆和加密，是在 socks5 的基础上进行本地加密和混淆发送给节点服务器，再由节点服务器进行解密后响应客户端的请求，而 socks5 协议是使用明文传输数据，也就是说，节点服务器解密后的 socks5 数据就是明文数据，但如果是 https，节点服务器解密后的仍然是本地浏览器加密后的数据，到达目标网站服务器才能被解密。
2. HTTP：
   特点：使用明文传输，没有秘密可言。
   安全性：数据可被窃取、篡改（知道你访问了什么网站，干了些什么）。
3. HTTPS：（也并非绝对安全）
   特点：使用密文传输，有效的防止了中间人攻击。
   安全性：访问网址可见，数据不可窃取、篡改（知道你访问了什么网站，但是不知道你干了什么）。
   但如果安装了这个节点服务器的根证书并添加到了受信任的颁发机构，HTTPS 就等同于 HTTP 了。
4. DNS 劫持：
   特点：只能劫持HTTP，但是在浏览器地址栏如果没有手动输入 https://，将会直接使用HTTP协议访问。
