# 解释这个数字

- **跑之前先写下决定。** 点名会改变一个决定的那个结果，以及噪声底。一次次运行之间的散布比效应还大时，停。
- **问「为什么不是两倍？」** 点名把结果框住的资源或代码路径，例如一个核、一把锁、磁盘、网络，或负载发生器自己。从一次运行期间的 profile 或系统计数器里得到它，再映射到源码。读代码猜出来的不是限制因素。你说不出这个数字为什么没有好上两倍，你就不知道自己量到了什么。
- **列出这个数字还可能在量什么，并用证据逐个排除。** 常见的是：错误、被跳过或被缓存的工作、根本没跑的代码、没调过的一侧（留在默认设置上）、噪声，以及一块小到端到端无关紧要的部分。
- **把证据和数字放在一起。** 把运行次数、散布和限制因素写进笔记，或放进一个链接的产物。

性能数字走 [benchmark-checklist](../benchmark-checklist/SKILL.md) skill 的完整流程。eval 结果对试验问同样的问题：是不是每次运行都做了任务，差距在多次试验和多个模型上是否成立，这个场景重不重要。

下面这些情况，说明你跳过了这一条：一次运行开始时还没有那个会改变决定的结果。一个数字背后的证据没有运行次数、没有散布，或没有点名的限制因素。省下的时间比改动的那一块本身花的时间还长。

和 [证明它能工作](../principle-prove-it-works/SKILL.md) 不同。那一条检查产出是不是真的。
