# Ketchup

把用户补上：这次聊天里，自他们在 `/ketchup` 之前写下的最后一条消息以来，变了什么，并帮他们理解每一次变化，不只是它现在停在哪。然后把每一个等着他们的决定摆出来，让他们只靠你的回复就能做。通知和 subagent 的结果不算他们的消息。假定用户记得自己的上一条消息，之后的一概不记得。

用 [`/bro`](../bro/SKILL.md) 的口气，不用它的任务：平白的话，短句，没有行话，像一个人把另一个人补上。说对用户变了什么，不说你怎么做的。说「测试通过了」，不说「CI 是绿的」。哈希、文件路径、命令、构建号和测试计数都省掉，除非用户需要其中一个才能行动。每个 PR、分支或 agent 都用用户会认得的名字来叫，不要用你发明的标签。一个事实需要上下文才说得通时，把上下文给上，或者把这个事实省掉。

## 收集变了什么

这一轮保持只读。图只从你已经有的东西做：不要改代码，不要启动应用或任务，不要发布任何东西。收集自那条消息以来你自己的工作、subagent 的报告，以及这次聊天里其他人的消息。检查这次聊天碰过的每个 PR、CI 运行或 agent 的当前状态。你要展示的每个数字，都对照它来自的事实核对，改了一个就说出来。

行动项是只有用户能做的一个决定或一步，例如一个产品选择、一次批准、一个不可逆的动作，或你没有的权限。任何仍在等用户的都算上，包括在他们上一条消息之前提出的。你自己还能做的工作不是行动项。绝不要编一个决定来填回复。用户没要、工作也不需要的一步不是行动项，除非它不可逆并且在等用户：给它一行，不给图。

一个决定可以盖住很多项，例如一组等待合并的 PR 里的每一个。对每一项，收集它的链接、它对用户改变什么、你这个选择背后的证据、它的风险，以及你的选择。决定需要、而你不知道的事实，写「未知」。你没有的链接就省掉。

## 写回复

把词花在决定上，不要花在故事上。发生了什么控制在 100 个词以内，图片不计，发生得少就更短。对用户什么都没改变的工作省掉。每一项大约 30 个词。回复随项数变长：两项加起来要远少于 150 个词，图片不计，三十项就要多得多。绝不要为了卡在词数里砍掉条目或把它们缩短：不要用一个数字代替一份列表，不要用一个链接代替一个条目。链接可以增加深度，但只靠回复必须足以做决定。

用一个短句开头，点名在等用户的是什么，或者说明没有东西在等。细节由行动项给出。什么都没发生，也没有东西在等用户时，这么说，然后停下。

然后显示发生了什么，图在前。把工作产出的截图和视频内嵌进去，然后是任何解释一次变化的图。然后按用户要求的每件事一条短列表：它有了什么结果，以及它是做完了、还在跑、失败了，还是没检查。每一行都写成你会说出口的那样：「搜索慢，是因为缺了索引」，不要「搜索评审：完成」或「搜索慢：缺索引」。点名路上发现并修好的任何 bug。每一行单独读也必须仍然为真。绝不要把仍在等用户的东西标成做完，行动项会说的东西这里省掉。摘要下面，最多给三行短的，改变用户所知或必须做的事。然后用一行点名你自己还能做的剩余工作。

然后列出行动项。问用户拥有的那个决定，例如合并、批准或挑选，并给出你的选择。你会先做的一步放进你的选择。必须先发生的事也放进去，不能撤销的事也放进去。一次决定涉及的每个 PR、issue 或 agent，给出编号或链接。在选项之间做决定时也要给。

让形状贴合这个决定。关于一项的决定是一条：这个决定、你的选择、它对用户改变什么、你这个选择背后的证据、它的风险，这一项只点名一次。多项共用一个决定时，决定和你的选择只写一次，然后每一项自己一条，风险最高的在前：它的链接和名字、它对用户改变什么、你这个选择背后的证据、它的风险。只有某一项的选择和这个决定的选择不同时，才点名它自己的选择。每一项的风险都给，即使很低，例如「风险低：只改了颜色。」等待的代价只有在它不止是耽误时才说，例如一个截止日期，或数据会丢。

在选项之间做决定时，给出工作权衡过的每一个选项，每个都写它给用户带来什么、代价是什么，有当前状态时也写上。这些代价就是这个决定的风险，所以不要再加单独的风险行。上面的截图已经显示这些选项时，把每个选项的收益和代价写在它的截图下面。

## 图

图是一幅画：一张截图、一段视频、一张 Mermaid 图、一张来自 `/visualize` 的图表或示意图，或一张生成的图片。Markdown 表格不是图，哪怕有前后对比的列。

一件事用图比用句子更好懂时，就画它：一个设计或系统怎么工作、一叠 PR 或依赖链以及每个 PR 的状态、一次修复的前后，或并排的选项。绝不要画一份状态列表、一份行动项列表，或一堆彼此没有连接的框。绝不要把一个事实说两遍，无论是在文字里，还是跨多张图。

每张图小到一眼能读：最多六个框，每个框最多八个词。标签写成一个人会说的平白的话，不要用「测试：通过」这种标签。需要一句话的事实放进正文。放不进正文的就不要。

改动看得见时，把截图和视频内嵌进去，不要只给链接。一处看得见的改动没有图时，把它的摘要行标成「还没有截图」，并在那里说屏幕上变了什么。图和图表从你拥有的事实来画：东西怎么连起来用 Mermaid 图，数字用 `/visualize` 图表。绝不要编一个数字，也绝不要画或生成一个你没抓到的屏幕。只链接存在的产物。
