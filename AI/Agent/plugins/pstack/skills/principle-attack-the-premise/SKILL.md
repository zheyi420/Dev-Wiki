# 攻击前提

两个或更多共用一个前提的修复都没过同一道闸时，怀疑前提，不要先怀疑那些修复。

- 把前提写下来：每一个失败修复都假定的那一句话。
- 下一次修复之前先检验它。找一个观察：前提如果是假的，结果会不一样，然后做出这个观察。看失败是怎么分布的，不只看它们有多大。
- 证据和前提矛盾时，找那些失败的共同点，而且是前提没有预言的。如果某一部分总是落在输的那边，就改掉把它放在那边的东西，不要再加一个事后收拾的机制。

前提写下来并检验过之前，不要开始下一次修复。
