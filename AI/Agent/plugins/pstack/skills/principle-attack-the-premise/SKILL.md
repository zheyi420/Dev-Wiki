# 攻击前提

两个或更多共用一个前提的修复都没过同一道闸时，怀疑前提，不要先怀疑那些修复。

**为什么：** 每一次失败的修复，都是对它所假定的那个信念的反证。在同一个前提上再做第三次修复，是把力气花在证据已经说明原因不在那里的地方。

**做法：**
- **把前提写下来。** 前提是每一个失败修复都假定的那一句话。
- **下一次修复之前先检验前提。** 找一个观察：前提如果是假的，结果会不一样，然后做出这个观察。看失败是怎么分布的，不只看它们有多大。按 [造杠杆](../principle-build-the-lever/SKILL.md) 把检查做成可以重跑的。
- **跟着证据走。** 它和前提矛盾时，原因在别处。找那些失败的共同点，而且是前提没有预言的。它确认了前提时，按 [修根因](../principle-fix-root-causes/SKILL.md) 问下一个「为什么」。先前的修复可能处理的是后果，不是原因。
- **去掉这个条件，不要去补偿它**，见 [偷懒协议](../principle-laziness-protocol/SKILL.md)。证据显示某一部分总是落在输的那边时，就改掉把它放在那边的东西。事后收拾的机制把原因留在原地，并且每次运行都多一份工作。

**停止：** 前提写下来并检验过之前，不要开始下一次修复。

这条原则和 [从第一性原理重新设计](../principle-redesign-from-first-principles/SKILL.md) 不同。那一条围绕一项新需求重建一个设计。这一条质疑的是当前设计所假定的一个事实。
