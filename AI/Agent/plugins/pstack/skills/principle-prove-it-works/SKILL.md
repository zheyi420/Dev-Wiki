# 证明它能工作

直接检查真实的东西，验证每一项任务产出。不要从替身、自我报告或「它能编译」推断。

**为什么：** 没验证的工作，正确性是未知的。间接验证（文件修改时间、输出是否新鲜、agent 自我报告、缓存的截图）感觉比直接观察便宜。按一个错误推断行动，代价远高于去源头看一眼。

检查真实的东西，不要靠替身：
- 直接检查进程是否活着，不要通过派生状态间接看
- 读实际的值，不要读缓存或派生的表示
- 验证失败时，先怀疑观察方法，再怀疑系统

## 能写成脚本就写成脚本

最强的证明是一个确定的脚本，能重新跑同一项比较，而不是看一次。把脚本写出来，跑它，并把输出留成产物，让评审者能重跑，而不是相信你的话。

把产物留给人看。只有工作很大或很复杂、事后必须能审计这条痕迹时才 commit，比如一次大移植或迁移（**show-me-your-work** skill）。
