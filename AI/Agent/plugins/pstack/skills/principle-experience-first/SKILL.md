# 体验优先

实现上的方便和用户的高兴冲突时，选高兴。

- 每个功能、控件和选项都必须有理由
- 少交付，交付得更好（三个打磨过的功能，胜过十个粗糙的）
- 选定之前先做原型（设计决定在一次性的 HTML 里比在生产代码里便宜）
- 把细节做对（过渡、对齐、间距、反馈、错误状态）
- 收紧核心循环（每个功能都该服务于中心工作流，否则就让开）

用户是消费这份工作的人。对 UI 来说是最终用户。对库或内部 API 来说是导入它的同事。下一个维护这段代码的工程师也是用户。用同样的方式权衡他们的体验，并从他们的视角解释影响。

基础应当服务于体验。基础性思维管的是工作的*顺序*。这条原则管的是*目标*。
