# 自己搞定

任务对不上任何 playbook 时，设计一个。写任何代码之前的交付物是工作流本身：一串阶段，严谨程度按任务调节，跑科学方法，并留下一条人走开之后还能审计的决定痕迹。

## 开始

打开一份待办，第一项是阅读 **poteto-mode** skill 的 Principles 一节。然后把下面这些阶段加进去。

## 阶段 A：框定

先落地，再承诺。在你能说出下面这些之前，不要开始这次运行：

- 完成的定义，写成一个可证伪的谓词（**prove-it-works** 原则 skill）。
- 范围，量化：大致的单位和工作量，加上落地时浮出的阻碍。
- 严谨级别，偏向高。单向门和爆炸半径大的，给更多。可逆、赌注低的步骤，给更少。严谨是闸门和产物，不是「再努力一点」。

在承诺一次长跑之前，先摆出框定和取舍。可逆的工作继续做（**never-block-on-the-human** 原则 skill），但一次要跑好几个小时的运行，值得一个检查点。

## 阶段 B：设计工作流

拆成原子的、可以独立落地的单元。最未知的风险排在最前。脚手架和验证在功能之前（**foundational-thinking** 原则 skill）。

- 在干活之前先建验证 harness，基线从改动前的状态抓下来，这样检查读起来是「旧值对新值」。
- 对单向门的设计决定，跑 **architect** skill（它会跑 **arena**）。形状已经具体的机械工作就跳过。在已经定下来的设计上再开一场 arena 是过度工程（**laziness-protocol** 原则 skill）。
- 决定什么要扇出。只沿着接缝并行，每个 worker 给自己的 worktree 或分支（**separate-before-serializing-shared-state** 原则 skill）。不要扇得过头。按 **poteto-mode** skill 的 Subagents 一节，为每个 subagent 按这项工作选定推理档位。
- 把设计好的阶段列表写下来。那份列表就是人要评审的东西。

然后执行这个设计。把它的步骤作为具体事项加进待办，放在阶段 C 和阶段 D 之间。每一步都按阶段 C 的循环纪律来跑，并把阶段 D 的日志织进去：每一步落地就记一行，而不是把整条痕迹留到最后。

## 阶段 C：跑循环

每个单元是一次实验。陈述假设，做最小的改动，在真实产物上对照谓词测量，推进了就留下，没有就回退。应用 **sequence-verifiable-units** 原则 skill，验证完这个单元再开始下一个，不要把检查攒到最后一批做。

- 靠检查产物来验证，绝不靠自我报告。某件事太容易就通过时，先怀疑观察方法，再怀疑系统。
- 委托出去的工作配一个评审。worker 如果在钻闸门的空子，就重置并收紧契约。如果闸门本身是错的，在它自己的一次改动里修闸门，不要绕开它。
- 判定是 VERIFIED、NOT VERIFIED 或 INCONCLUSIVE。无结论不是通过。不要藏起一个负面结果。

## 阶段 D：留下审计痕迹

通过 **show-me-your-work** skill 记录这次运行。figure-it-out 的工作通常足够大，值得把痕迹 commit 进去，让评审者能在 PR 里读到。痕迹加上 diff，才让人回来时信得过这项工作。

## 阶段 E：验证并交回

对照阶段 A 的谓词检查整体，在真实产品上，而不只是在 harness 上。把反复出现的纠正编成闸门、lint 规则、检查或脚本（**encode-lessons-in-structure** 原则 skill）。

**回复：** 你设计的 playbook、严谨级别和为什么、决定痕迹的路径、对照谓词已经验证了什么，以及还有什么敞着。
