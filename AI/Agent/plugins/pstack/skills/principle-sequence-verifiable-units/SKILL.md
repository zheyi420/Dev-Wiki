# 把工作排成可验证的单元

把工作排成一串小单元，每个单元结束于一个你能检查的状态，当前这个没变绿就不要前进。

**为什么：** 在造成破损的那个单元抓住它，定位很便宜。一批做完才抓住，破损就被埋住了，而且你已经在坏的底座上继续盖。把同样这些单元排成评审者能重放的交付，就把「相信我」变成「看它先变红，再变绿」。

**执行。** 在一次扫荡、一次迁移，或任何一串相似的编辑里，验证完这一处改动再开始下一处。每个单元是一个前后括号：已知良好的状态，一次改动，跑检查，然后继续。先变基到干净的主干，这样每一次检查都是对照真实基线。杠杆在做这些编辑时，每个单元的检查几乎免费。还是要跑。

**交付。** 按能证明这项工作的顺序叠 commit 和 PR。标准形状是失败的测试在前，修复叠在上面。其他叙事顺序可以是：重塑之前先做减法，处理之前先抓住基线，功能之前先搭脚手架。每个 commit 自己能落地，整段序列读起来像一个论证。

这是 **prove-it-works** 原则 skill 的排序互补：它让每次检查都是真的；也是 **build-the-lever** 原则 skill 的互补：它让每个单元的检查变得便宜。
