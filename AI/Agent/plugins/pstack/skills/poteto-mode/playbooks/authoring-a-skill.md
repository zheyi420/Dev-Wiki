### 编写或修改 skill

**这个 skill 的文风归你。**

1. 使用 **create-skill** skill（Cursor 内置，用来编写 SKILL.md）。
2. 校验这个 skill：frontmatter 含有 `name` 和 `description`，被引用的文件都在，跨 skill 链接都能解析。
3. 结构上可测就写测试用例。主观的就跳过。
4. 跑 **开 PR**。

拿不准，就删。只留会改变一个决定的散文。让它去做这件事，把理由省掉。只有规则不解释就会让人糊涂时才解释。语气和范围相称。按 **encode-lessons-in-structure** 原则 skill，指向结构性来源（类型、README、配置）。委派给别的 skill 时给出路径。不要复述。一条你反复撞上、却还没被记下来的工作流 → 提议一个新 skill。

**回复：** 这个 skill 的摘要、关键设计决策、校验笔记。
