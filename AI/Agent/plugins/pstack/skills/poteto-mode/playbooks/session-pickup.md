### 接手会话

**恢复点归你。读先前的轨迹，不要重做。**

1. 找到先前的轨迹。当前工作区 `agent-transcripts/` 目录下的本地对话记录（系统 prompt 会给出路径。不要跨 `~/.cursor/projects/*/` 做 glob，那会跨过工作区边界，读到无关项目的私人聊天）、一条 cloud-agent URL，或一个已经推送的分支。先读元数据概览和最后几条消息，再往回扫决策点。长对话记录放进 subagent 解析，收束后的时间线留在主线程（**principle-guard-the-context-window** skill）。按 Subagents 一节，为每个 subagent 按这项工作选定推理档位，以及快速或标准速度。
2. 重建操作状态。分支和 worktree、已经落地的内容（相对基线的 `git log`、`git diff`）、还开着的 todo、已经做出的决定。先前的轨迹是权威输入。克制住重新推导它的偏向。
3. 对照已完成和待办。拿已经交付的对照原来计划的，点出恢复点，不要重跑先前的复现，也不要重做已完成的工作。走一遍「让我从头验证」，等于把这份权威轨迹当成不可信。
4. 把剩下的工作分流到对应的 playbook，并选定裁决：继续执行、交付一条已经完成的建议、追认或推翻先前的结论，或者给一次失败的运行做复盘。接手会话这个 playbook 到这里结束。其余归分流过去的那个 playbook。
5. 在真实制品上，对照原始目标核对这些继承来的说法（**principle-prove-it-works** skill）。先前一份自报通过，不算证据。

**回复：** 上一个 agent 停在哪里、你继承了什么、重做了什么（最好什么都没重做）、恢复点，以及结果。
