### 评估

**实验设计归你。规划、设盲、运行、综合。**

**设盲的不可协商项：**

- 候选看得到的任何目录、文件或 prompt 里，都不要出现 `eval`、`test`、`judge`、`experiment`、`rubric`、`score`、`compare`、`benchmark`、`candidate` 或 `arena`。
- 给候选的 prompt 要像用户随手写的请求。写目标，不写这场测试本身。
- 不要放会把链路问出来的暗示。不要让候选列出用了哪些 skill、原则或文件。只笼统地要设计笔记。链路有没有跟上，看代码形态来打分，不看自我报告。
- 把目录名和 slug 脱敏。用用户可能起的、像项目的名字。
- 不要告诉候选还有别的候选。
- 评审可以知道自己在做评审，但只能按脱敏后的标签看输出，绝不能凭模型名。
- 比较两个变体时：一个评审用同一把尺子、一次评完两套，并且不知道每套出自哪一个。

**步骤：**

1. **框定。** 写明在测哪个变体、怎样的行为算成功。评分标准（3-6 条具体标准）只写给评审。对候选保密。
2. **搭好脱敏环境。** 每个候选一个工作目录，变体已经放好。放进自然任务会有的上下文：项目骨架，以及候选本来就会去读的 skill。
3. **写一条自然的 prompt。** 用户会输入的那种。不要泄露正在测什么。
4. **拉起 N 个并行候选**，按 **arena** skill 的阶段 B 放在不同模型上。各自在自己的脱敏目录里工作。每个候选拿到同一条 prompt。按 Subagents 一节，为每个 subagent 按这项工作选定推理档位，以及快速或标准速度。
5. **拉起一个设盲的评审**，按 **arena** skill 的阶段 C 放在另一个模型家族上。评审按脱敏标签和评分标准看输出，绝看不到模型名。
6. **凭对话记录核对链路，不凭自我报告。** 读每个候选在当前工作区 `agent-transcripts/` 目录下的本地对话记录（系统 prompt 会给出这条路径）。不要跨 `~/.cursor/projects/*/` 做 glob。那会跨过工作区边界，读到无关项目的私人聊天。看每个候选实际打开了哪些文件。链路有没有跟上，凭它真正读过的文件加上代码的形态来打分，绝不凭候选自己的说法。
7. **你自己读每个候选的输出**，从头到尾。对照评审的裁决。两边不一致，说明某个模型有偏向，或者评分标准含糊。然后做综合。

**回复：** 在测的变体、评分标准、每个候选的笔记、评审的裁决、你的综合，以及是否建议把这个变体推上去。
