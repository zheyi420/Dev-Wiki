### 自主运行

**退出条件归你。先定义怎样算完成，然后不停地开到那里。**

1. 第一轮开始之前，把退出条件写成可核对的谓词（测试全绿、复现已修好、全部 N 个 PR 已合并、像素 diff 为零）。
2. 用 Cursor 的 `/loop` 命令选定唤醒机制（这是内置命令，不是 pstack skill）。要盯的事件（CI、一次合并、一个 ref 在前进）就配一个监视 subagent，事件一到就叫醒你，再用一个间隔很长的定时心跳兜底。没有事件，就用固定间隔的心跳，间隔按结果值得再查一次的时机来定。按 Subagents 一节，为每个 subagent 按这项工作选定推理档位，以及快速或标准速度。
3. 每一轮只做证据支持的最小改动，拿谓词验证，有推进就 commit，没起作用的改动丢掉。「也许有用」的双保险要回退，不能留着一起带下去。
   通过 **sequence-verifiable-units** 原则 skill 把工作排成序列，验证完一个单元再做下一个，不要把检查攒到最后。
4. 途中凡是支撑目标的发现，都归你处理。坏掉的 skill、相关 bug、不稳定的验证器、评审噪声、工具故障、没人接的后续、修得了的漂移，都由你自己经 poteto-mode 处理。带外修复各自单独开 PR。不要把可逆的工作搁下来等人类，也不要使用 `AskQuestion`。只抛出这些：不可逆的动作、没有实验能裁定的真正产品或偏好判断，或者一条真的死路。谓词始终是主线，每次旁路修完都回到它。
5. 每一轮都用 **show-me-your-work** skill 留检查点，一行记下改了什么、谓词有没有移动。
6. 谓词达成就停。平台期不是停，所以继续，并换打法冲过去。真的走不通就抛出来，不要空转。绝不能放宽谓词来宣布胜利。

**回复：** 退出条件、跑了多少轮、落地了什么、丢掉了什么、谓词的最终状态。
