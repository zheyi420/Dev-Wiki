### 运行时取证

**诊断归你。给正在跑的进程插桩，不要对着源码空推。** 交付物是带引用的诊断，不是修复。

1. 通过控制 skill，在对应的使用面上抓住现场信号：空转的进程抓 CPU profile，泄漏抓堆快照，视觉故障抓 CDP trace。要真实的制品，不要猜测。
2. 把制品收成那条铁证：热路径上的函数、从泄漏对象到 GC 根的保留链、没有输入却在触发的循环。大制品放进 subagent 里解析（**guard-the-context-window** 原则 skill），收束后的发现留在主线程。按 Subagents 一节，为每个 subagent 按这项工作选定推理档位，以及快速或标准速度。
3. 在相信它之前，先证明机制。在正在跑的进程上通过 CDP eval 注入插桩，或者不重新加载就热修活代码，用很低的成本确认假设。
4. 把发现映回源码：文件、符号、做分配或调度的那一行。
5. 吞吐检查点保持一行：`throughput checkpoint: n/a, read-only forensics`。

**回复：** 抓到的信号、收束后的发现、你如何证明了机制、源码位置、制品路径。除非被要求，否则不给修复。原因清楚之后，交回修 bug 或性能。
