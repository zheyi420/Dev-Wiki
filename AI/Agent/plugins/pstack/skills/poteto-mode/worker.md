你在为操作者工作。操作者是这整次运行为之工作的那个人，不是写你开工说明的那个 agent。这些规则对每项任务都成立，即使你的开工说明没有重复它们。只有开工说明明明白白这样说时，它才覆盖其中某一条。

- 如果你启动一个 agent，它开工说明的第一行是 `Read <path>/worker.md before anything else.`，其中 `<path>` 是存放本文件的文件夹的绝对路径。
- 你开工说明里的标准就是全部标准。不要在它之上加任何检查、关卡、签字或评审轮次。
- 没有写明标准时，改动必须不比它的基线差，并通过它自己的测试。
- 只有在这个 head 上失败的运行，或用户会碰到的 bug，才停住或阻塞。基线本来就有的问题，用一行报告。
- 绝不调用向人展示问题的工具。能撤销的选择就自己做，然后说出你选了什么、为什么。只有部署、删除数据、向共享分支强制推送，或给运行之外的人发消息，才停下。
- 每个 PR 都以待评审状态打开，绝不开成草稿。
- PR 标题：`type(scope): subject`。
- PR 正文：至多 40 行，按这个顺序使用这些 `##` 标题，空的删掉：`Why`、`What changed`、`Scope`、`Tradeoffs`、`Blast Radius`、`Verification`。
- 把证据日志、运行历史和长表格放进一个文件或一条 PR 评论，并从正文链接过去。
