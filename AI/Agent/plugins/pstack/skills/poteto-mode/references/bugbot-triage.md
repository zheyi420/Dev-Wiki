# Bugbot 分诊

看护 PR playbook（`../playbooks/babysit.md`）处理 Bugbot 或评审自动化评论时，用这份参考。目标不是默认无视 Bugbot。目标是不再把每条评论都当成必须改代码。

## 判定标准

行动前，先给每条 Bugbot 讨论串分类：

- `fix`：评论指出了一个说得通的正确性、安全、隐私、数据丢失、认证、计费、迁移、幂等、竞态，或已交付行为的问题。在拥有这段代码的最低 PR 里修掉，然后用 commit SHA 回复，并解决讨论串。
- `dismiss`：评论符合已记录的低风险噪音模式，而且当前代码或上下文证明，这个担忧不需要改代码。用简短理由回复，并解决讨论串。
- `ask`：评论是新的、高严重度的、与安全、隐私或数据相关，或含糊不清。问用户，不要猜。

拿不准就问。跳过一条吵的代码质量评论，便宜。漏掉一个真正的数据或安全 bug，不便宜。

## 已学模式的格式

以后的模式按这个形状加：

```markdown
### <short pattern name>

- Confidence: candidate | recurring | strong
- Skip when: <conditions that must be true>
- Do not skip when: <risk boundaries>
- Example signal: <phrases or code context that identify the pattern>
- Source: <PR/comment URL or short historical note>
```

一两个例子用 `candidate`。多次真实驳回之后用 `recurring`。只有模式很窄、反复核实过，而且风险低时，才用 `strong`。

## 反复出现、可以跳过的候选

### 有意的 UI 或设计系统视觉变更

- 置信度：candidate
- 何时跳过：PR 描述、截图、设计评审或附近代码已经把视觉变更写明，而 Bugbot 评论只是在复述：某个共享的视觉默认值变了。
- 何时不跳过：评论指向无障碍、焦点可见性、键盘导航、色彩对比度，或 PR 并没有有意改动的组件 API 契约。
- 例子信号：关于焦点描边、按钮尺寸、间距，或共享组件视觉默认值的评论，负责人回复「有意」或「故意的」。

### Bugbot 看不到的栈上层或 stack 内部用法

- 置信度：candidate
- 何时跳过：Bugbot 把某个导出、组件、辅助函数或文件标成未使用，而当前托管平台的 PR 列表和 diff、更上层的 diff 或 PR 上下文表明，stack 里更后面的 PR 用到了它。
- 何时不跳过：当前 PR 不在某个 stack 里，这个符号是公开 API，或所谓的栈上层用法核实不了。
- 例子信号：「导出的组件从未被使用」，人的回复类似「栈上层在用」。

### 并行实现期间的临时重复

- 置信度：candidate
- 何时跳过：PR 有意复制少量代码，让一条新路径与一条正在删除、替换或验证的旧路径保持并行。
- 何时不跳过：重复的代码改动了安全、计费、数据访问或 API 行为，或者一个长期共享抽象明显能降低风险。
- 例子信号：「重复很严重」或「校验逻辑重复了」，负责人解释旧路径会被删掉，或这份重复是有意保持局部的。

### 现有框架或组件不变量已经覆盖这条警告

- 置信度：candidate
- 何时跳过：这个担忧已经由共享组件、框架契约、类型不变量，或当前 diff 及附近代码里看得见的单一事实来源保证。
- 何时不跳过：不变量只是假定、并未强制，依赖时序，或跨过异步或状态边界，值可能各自走偏。
- 例子信号：内层 popover 缺少 max-height 的评论，而共享 popover 已经在强制视口边界；或者可空值的评论，局部检查过的值和传下来的值来自同一来源。

### 负责人声明的后续，或推迟的清理

- 置信度：candidate
- 何时跳过：PR 负责人明确说这是已知后续，当前 PR 没有让行为变得更差，而且评论不在高风险区域。
- 何时不跳过：agent 在没有负责人意见时动手，问题是中等或高严重度的产品行为，或者推迟会把一个新回归合并进去。
- 例子信号：「这个以后再说」或「我们最后会删掉它」。

### 自行撤回，或写明是误报的规则评论

- 置信度：recurring
- 何时跳过：评论正文，或之后的 Bugbot 回复，明确写着发现已撤回、已符合，或是误报，而且 agent 能在本地核实相关规则。
- 何时不跳过：唯一的证据是人在高风险问题上说「误报」，却没有解释。
- 例子信号：一条文件命名规则评论，正文说这个文件已经符合。

## 默认要问

这些类别不要自动跳过，哪怕之前的 PR 驳回过类似的东西：

- 安全、隐私、认证、计费、数据保留、训练数据和权限边界方面的发现。
- 高严重度的发现。
- 迁移、schema、幂等、并发和跨系统行为方面的发现。
- 建议的修复很小，又能明显降低风险，且不改变产品意图的评论。

历史数据显示，人有时会驳回安全或数据流方面的评论。把这些当作负责人的判断，而不是全团队的跳过规则。

## 近期看护里的候选收获

看护过程中或之后，把看起来对团队有用、但还不够成熟的新候选收获追加到这里。一旦好几个 PR 确认了模式，优先把反复出现的候选提升到上一节。

### 手动重做浏览器原生行为

- 置信度：candidate
- 何时跳过：实际上从不跳过。diff 若用手动等价物替换浏览器原生行为（原生 sticky 换成 JS 定位的克隆，原生滚动定位换成转发的滚轮或触摸事件，绘制顺序的遮挡换成 mask 或 clip-path），Bugbot 针对这段代码的逻辑 bug 发现一直站得住。
- 何时不跳过：发现涉及事件转发的缺口（滚轮 deltaMode、触摸平移、边缘的滚动串联、点击容差）、mask 或 clip 的命中测试偏差，或这类代码里 observer 与 React 状态的时序竞态。默认去修。
- 例子信号：「mask 不影响命中测试」「遮罩挡住了滚轮滚动」「忽略了 deltaMode」「在 React 应用状态之前，就在 IntersectionObserver 回调里跑了」。
- 来源：一个 sticky 遮挡 PR。六轮 Bugbot，大约十八条发现，每一条都修了，没有驳回。

### 契约测试漂移的说法，花一条命令就能核实，先跑测试

- 置信度：candidate
- 何时跳过：核实本身永不跳过，它只花一条命令。PR 若交付了钉住协议或文档散文的契约测试（扫 SKILL.md 的正则，或文档措辞的快照），而 Bugbot 声称「测试不再与文档匹配」（或反过来），分类之前先在 PR 尖端跑那个测试。跑红了，就是从经验上确认了说法。跑绿了，就是驳回回复里的具体反证。
- 何时不跳过：不适用。这是核实上的捷径，不是驳回模式。注意，多轮之后倾向驳回的启发式在这里会打偏。钉住散文的测试之所以漂移，正是因为更早的修复轮改了散文。
- 例子信号：在一个 PR 上说「契约测试漏了修复前的等待」。更早的修复 commit 改写了被钉住的那段。在尖端跑测试，恰好失败在被点名的那条断言上。
- 来源：一个钉住散文的 PR，八轮 Bugbot。第 7 轮的说法是真的，尽管更早每一轮都已修复并解决。

### 同一 PR 里，更晚已经修好的过期安全评审

- 置信度：candidate
- 何时跳过：一次 agent 安全评审（或类似评审）声称缺少某次授权或校验调用，而当前 PR 尖端已经清楚地包含那道确切的门（带测试），通常是评审跑完之后，由更晚的加固 commit 加上的。
- 何时不跳过：被点名的辅助函数对讨论中的主体是空操作，检查跑在它所守卫的副作用之后，或缺少对所称主体的覆盖。
- 例子信号：一条 HIGH「缺少授权检查」，而那道确切的守卫在尖端已经于副作用之前被调用。
- 来源：一个 webhook 端点 PR，它的加固 commit 晚于那次评审。

### 放宽一条故意收窄的错误条件，会掩盖真正的错误

- 置信度：candidate
- 何时跳过：发现要求把一个窄的错误条件（某个具体的 `errno`、错误码或状态类别）放宽成兜底，而这种窄本身编码了一个真实区别。典型形状是依赖回退以 `ENOENT` 为门：「二进制没装」和「命令跑了但失败了」是两回事。对任何非零退出都重试，会把一次正当的失败（找不到、认证过期、网络）再对着回退跑一遍，然后报出回退的错误，把真错误藏起来。
- 何时不跳过：窄条件漏掉了同一类别里的另一种情况（另一种「二进制不可用」的 errno，例如 `EACCES`，或另一种传输层失败），未处理的路径会丢数据或留下部分状态，或者重试是幂等的，而且原始错误仍然会被报出来。
- 例子信号：「只在 X 以 ENOENT 失败时才重试……即使有一个能用的 Y，也从不尝试回退」，指向的代码里，回退是为缺失的依赖而存在，不是为失败的操作。
- 来源：一个 CLI 重命名 PR，它的回退是为缺失的二进制准备的，不是为失败的命令。
