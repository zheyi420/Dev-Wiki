# 设计红旗

综合之前，筛每一份候选。红旗是修改或否决这个形状的理由。

## 浅模块

浅模块露出很大的接口，却藏住很少的复杂度。用公共表面背后藏住的能力和策略，相对这个表面的大小，来判断深度。偏好一个简单接口，背后是实在的行为。

不要把深模块和深调用链搞混。深调用链把理解散落在各层。深模块把能力集中在一个接口后面。

找这些迹象：

- 调用方要协调好几个方法才能完成一次操作。
- 公共选项暴露了内部阶段或实现选择。
- 学会接口并不能让调用方免于去学实现。

## 信息泄漏

信息泄漏让多个模块依赖同一个内部决定。一种表示、策略或协议细节出现在不止一处，所以改它需要协调编辑。

把传输或线路类型公开再导出就是泄漏。在接口后面把外部数据解析成领域类型。存储模式、框架对象和协议细节保持私有。

## 按时间拆分

按时间拆分是按执行顺序组织模块，而不是按它们拥有的知识。分开的加载、校验、变换和保存阶段，常常把同一种表示和它的不变量重复跨过好几道边界。

围绕领域知识和所有权来组织代码。在不同时间运行的方法，只要保护的是同一批决定，仍然可以属于同一个模块。

## 透传方法

透传方法把同样的参数原样转给另一个形状相同的方法。它加了一层，却没有藏住复杂度。

删掉它，或者把责任移到能完成这次操作的模块。只有在它加上策略、适配或一个不同的抽象时，才保留这道转发边界。

## 所有权分裂

不止一个模块写同一块状态，或各自留一份副本。一个 agent 改了一个写入者，看不见其他的，于是它们的规则分叉。

每一块状态给一个所有者。其他模块读它，或请所有者去改它。

## 一件事有两种做法

设计支持不止一种方式做同一件事。agent 抄到哪一种就用哪一种，于是每一种都继续获得调用方。

只留一种。把调用方从其他方式迁走，并在同一次改动里删掉它们。

## 可导入的内部

调用方能导入一个模块的内部。agent 走能编译的最短路径，于是直接导入它们，它们就变成了接口的一部分。

让内部从模块外面不可达，这样从外面导入就会让构建失败。

## 手工同步的列表

两个或更多地方列出同样的条目，加一个条目就要改每一份列表。agent 看见一份就只更新那一份。

留一份列表，其他的从它派生。如果一份列表不能派生，就让列表不一致时构建失败。
