# 先拆开，再串行化共享状态

并发行动者可能写同一个文件、分支、键或对象时，先问他们需要的是一个共享对象，还是各自在发布独立的事实。默认给每个行动者自己的文件、键、分支或状态目录，只在读取状态的地方合并。两个 worker 各把自己的字段写进同一个 `state.json`，仍然是共享变更。

只有一个共享写入目标是真正的不变量时，才用结构串行化访问（锁文件、单一写入者、顺序阶段、比较并交换）。指示不是并发控制，「我们需要一把锁」是一种要先检查的坏味道。
