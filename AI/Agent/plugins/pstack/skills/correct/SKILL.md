# Correct

操作者一直在为同样的错误纠正这个仓库里的 agent。改这个仓库，让下一个 agent 做不出这些错。

假定每个贡献者都是一个 agent：它只看见自己打开的文件，抄最近的例子，走能编译的最短路径。把仓库设计成：从一个文件看起来对的改动，对整个仓库也是对的。

## 找出错误类别

先读最近的 commit、回退、评审评论、agent 指示文件，以及解释权宜之计的注释。把错误分成类别。一个类别发生过两次才算数。

## 在能起作用的最高一层修每一类

1. **用架构消掉它。** 每一块状态一个所有者，每一项任务一条受支持的做法。藏起内部，让错误的导入失败。用手写同步的多份列表换成一个事实来源。删掉 agent 会去抄的旧做法和死代码。
2. **用类型强制它，让坏状态写不出来。** 如果坏代码仍然能编译，加一条 lint 或 CI 检查，错误信息点名应该改用的文件、类型或函数。如果这个模式已经很常见，只在一次改动又增加更多时才失败。
3. **测行为。** 修掉或删掉那些在它检查的行为坏掉时仍然通过、或者只有内部实现变化时就失败的测试。
4. **文档或 agent 规则放在最后，只留给需要判断的决定。** agent 跳过它们时，什么都不会失败。

## 修，并证明

然后现在就修最常见的类别，每个一类一个 commit。证明每一项新检查都会在一个真实的历史错误上失败。在本地和 CI 里跑同一条命令。例外写在出错的那一行，带上理由、到期日，以及一个人的批准。

## 维护规则表

最后，在 agent 指示文件里留一张表，把每条规则和强制它的东西配成对。操作者纠正你时，修这个错误，并补上规则。如果规则已经在、却没有东西强制它，那就是重复，所以在同一次改动里把它修到最高一层。某类错误已经不可能发生时，删掉对应规则。

**回复：** 每一类，带上证据、你选的层级，以及为什么更高一层行不通。
