# Ketchup 视频

遵循 [`/ketchup`](../ketchup/SKILL.md)，但用一段短的带字幕视频来显示发生了什么，代替它的摘要和图。窗口从用户在 `/ketchup-video` 之前写下的最后一条消息开始，不是从更早的任何一次 `/ketchup` 之前开始。在仓库之外写视频、渲染视频，是它只读规则的唯一例外。回复是 ketchup 的开场句、嵌入的视频、一行点名你自己还能做的剩余工作，以及行动项。视频显示一次决定的选项时，每个选项都用视频给它的名字来称呼。渲染失败时，用一行说出来，并且只给那些决定。

## 幻灯片

用工作产出的截图、录屏、diff 和数据，不要用聊天里关于它们的散文。动笔之前，写下用户离开时应该带走的那一句话，以及每张幻灯片一行。去掉不改变用户所知的每一张。最多 10 张，更少更好。这两条笔记都不进回复。

每张幻灯片只讲一个点。幻灯片建在同一张图上，一张一张地改它，不要切到一张无关的图。一种颜色或形状在每一张上意思相同。用图来显示工作，例如一个系统怎么工作、一叠 PR 以及每个 PR 的状态、一次修复的前后，或并排的选项。用箭头、高亮和运动指向变了的地方。幻灯片绝不是一份项目符号列表、一份状态列表、一张表，或一堆彼此没有连接的框。

文字收到最少。把每个标签放在它命名的东西上，用一个人会说的平白的话，不要用「测试：通过」这种标签。不要给图已经显示的东西再写说明，也不要把一个事实说两遍，无论是跨幻灯片，还是在它们下面的文字里。

显示用户要求的每件事有了什么结果，以及它是做完了、还在跑、失败了，还是没检查。绝不要把仍在等用户的东西显示成做完了。显示路上发现并修好的任何 bug。一处看得见的改动没有截图时，在它的幻灯片上说出来，并点名屏幕上变了什么。只从你拥有的事实来画。绝不要编一个数字，也绝不要画一个你没抓到的屏幕。

## 字幕

每张幻灯片给一行短字幕，大约十个词，用你告诉用户的那种说法说出它的点，并且只根据这张幻灯片显示的东西。说这张图意味着什么，不要把标签念出来。字幕放在幻灯片下方的一条里，每张高度相同，除了字幕什么都没有，这样它永远盖不住幻灯片。字号小，但视频以聊天大小播放时要能读。

## 渲染

渲染一段无声的横向视频，例如 mp4，幻灯片之间有运动。每一帧都是幻灯片本身，边到边，在它的字幕条之上。帧从幻灯片做出来，绝不要靠录屏。把每条字幕烧进它那张幻灯片的帧里，让它在这张幻灯片的整段停留期间都留在屏幕上。停留是一张幻灯片完全在屏幕上的时间，不算进入或离开它的运动。每张停留到够读它新增的词，每三个词至少一秒。一张幻灯片新增的是它的字幕，以及上一张没有的每个词，包括它改掉的标签。第一张新增它的全部词。截图里面的词不算。

嵌入视频之前，检查渲染出来的文件。以聊天大小看每张幻灯片的一帧，检查字幕能读，并且什么都没盖住。测量每次停留时，把文件的帧和幻灯片对上，不要用静帧检测器。静帧检测器会把淡出淡入的淡端也算成静止。拿每张幻灯片新增的词数，去对它测到的停留。在那段时间里读不完的幻灯片就改，再渲染，再检查。
