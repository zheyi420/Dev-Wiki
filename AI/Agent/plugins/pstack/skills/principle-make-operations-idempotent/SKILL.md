# 让操作幂等

把操作设计成：无论跑多少次、上一次停在哪里，都会收敛到正确状态。每一个改变状态的操作都要回答：「跑两次会怎样？上一次跑到一半崩了会怎样？」

**为什么：** 命令、生命周期操作和处理循环运行的地方，崩溃、重启和重试是常态。如果半成品状态会改变下一次运行的结果，每一次重启都变成一次调试。

**想法：** 每一步都从已经存在的状态推导，而不是从上一次运行打算做什么推导。读当前状态，把它和目标比较，只应用差额。这样写的步骤重复跑是安全的，因为再跑一次会发现没有剩下的事。

一次运行留下的任何东西，比如锁、临时文件、写了一半的记录或认领的任务，下一次运行都必须能认出它已经过期。判断过期要靠在上一次运行任何停点都仍然成立的证据，而不是只在常见情况下成立。下一次运行无法判断的标记，会把每一次崩溃都变成手工清理。例如，先写到临时路径再改名就位，或者按内容比较产物，而不是按创建顺序。

**检验：**
1. 连续跑两次会怎样？
2. 上一次运行在每一个可能的点崩溃会怎样？
3. 再执行一次会收敛到同一个终态吗？

如果任何一个答案是「取决于留下了什么状态」，这个操作就需要一个调和步骤。
