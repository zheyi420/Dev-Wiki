# Interrogate

对手试图打破一次改动或一个设计。只有一次运行证明了的发现才留下来。报告这些发现。不要应用修复。

## 框定

范围是用户点名的东西。否则就是这条分支相对基分支的合并基点的 diff，一直算到工作树。用 **in-your-own-words** skill，从用户的消息、commit 和 PR 描述里说出意图。意图不清楚时问用户。

## 扇出

跑 **arena** skill 的阶段 A 第 3、4 步和阶段 B，做四处改动。读 `interrogate reviewers` 那一行，代替 `arena runners`。把范围内未 commit 的改动复制进每个 worktree。把每个对手拉成 `generalPurpose`。代替 arena 的任务和理由，给每个对手范围、意图，以及这份简报：

> 打破这次改动。用一次对着真实代码的运行证明每条发现，例如一个失败的测试、一段复现脚本，或显示出错误行为的命令输出。对设计或计划，跑一个原型，或探当前的树。复现留在你自己的 worktree 里。每条发现报告标题、确切命令、它打印的输出，以及意图要求的输出。你没跑过的一律不写。这包括风格、命名、结构，以及要等未来一次改动才要紧的风险。没有发现是合法结果。

## 核实

按 arena 阶段 F 核实每条发现，把命令重跑一遍。输出显示出失败，并且这次失败打破了意图时，留下这条发现。其余丢掉。根因相同的发现合并。

跳过 arena 的阶段 C、D、E。对手找到的是不同的失败，所以结论保留每一条核实过的发现，不是某一个对手的清单。

## 输出

- **意图**：重述。
- **发现**：每条核实过的发现给出命令、它的输出、它怎样打破意图，以及找到它的对手。一条都没留下时，说「没有核实过的发现」。
- **丢弃**：对每个对手，丢掉的发现有多少，以及为什么。
