# 造杠杆

工作不平凡时，造一个做这件事的工具，不要用手做。

codemod、生成器或脚本每次都按同样的方式干活，重跑不花钱。工具是一份产物，评审者能读、能重跑，用来核对工作。手做的改动只能靠重做来再验证。一个确定的脚本把「相信我」变成「跑这个」。

默认造杠杆。只有任务平凡时才跳过：一眼就能看完的两三处显然改动。

- 先用手做第一个单元，学会配方，再造工具。把它在那个单元上重跑，和你手做的版本做 diff，以此证明它。让杠杆重跑是安全的。
- 编辑用 codemod 或脚本，重复的文件用生成器，分析用倒进 sqlite 的查询，验证用一个可重跑的检查。
- 确定的杠杆胜过扇出。工具能一遍处理每一个单元时，你自己跑。不要扇出受托方去手改脚本能做的事。
- 把工作扇出给 subagent 时，把杠杆写成一份他们都会读的 skill：配方、验证契约、不许碰的围栏，放在同一份产物里。把它放在受托方的写入范围之外，这样他们不能悄悄改契约。
- 应用这条原则会产生一个文件。你引用了它，diff 里却没有 codemod、脚本、生成器或受托 skill，你就没有应用它。
- 工作活过这次会话时，把杠杆 commit 进去。

门槛是平不平凡，不是重不重复。一次性的工作，只要杠杆是让它可核对的东西，仍然值得造。按 [偷懒协议](../principle-laziness-protocol/SKILL.md)，造能做完或证明这件事的最小脚本，绝不要造一个框架。

和 [把教训写进结构](../principle-encode-lessons-in-structure/SKILL.md) 不同。那一条把反复出现的指示变成持久的护栏。这一条是眼前这份工作的吞吐和可评审性。要给验证本身写脚本，见 [证明它能工作](../principle-prove-it-works/SKILL.md)。
