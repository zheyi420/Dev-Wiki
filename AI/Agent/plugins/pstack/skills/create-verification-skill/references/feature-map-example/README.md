# Notes 验证地图

这个目录是验证 Notes 面向用户行为的维护来源。驱动应用之前先读索引，然后把匹配的功能文件当作配方。

## 基线前提

- 用一个一次性数据目录，在 `http://127.0.0.1:4173` 启动 Notes。
- 设置 `NOTES_DATA_DIR=/tmp/notes-verify-$RUN_ID`，让并发运行不共享状态。
- 种下标题为 `Quarterly plan` 和 `Grocery list` 的笔记。
- 把 `control-notes` 和 `notes` CLI 放到 `PATH` 上。
- 运行 `control-notes doctor`，并要求预期的 URL、数据目录和构建修订。
- 绝不驱动不是这次验证运行启动的实例。

## 驱动约定

- 每份配方都从基线状态开始，除非它的前提另有说明。
- 优先 ARIA 角色和无障碍名称，不要用 CSS 选择器或 DOM 位置。
- 每条命令都按字面对待。引号里的名字和 flag 保持原样。
- 浏览器动作经 `control-notes browser` 跑。
- 终端动作经 `control-notes cli -- <command>` 跑。
- 变更之后恢复种子数据。清理时不要去掉证明产物。

## 证明与跳过报告

- 抓下用户动作和随之而来的状态，不只是最终画面。
- UI 证明包括一份 ARIA 快照，以及一张能看见应用身份的截图。
- CLI 证明包括命令、stdout、stderr 和退出码。
- 变更证明包括对存储值的第二个只读视图。
- 每份产物都记下功能 ID 和用到的入口。
- 到达不了的路径，报告尝试过的命令和没满足的前提。
- 不要把一个跳过的入口报告成经另一条路径验证过。

## 功能条目契约

每个功能文件以一个 H1 标题开始，加一段描述用户可见行为的话。然后按这个顺序正好用四个 H2。

1. `Sub-features` 列出短 ID，每条行为一行。
2. `How to get to it (user POV)` 列出每一个用户入口。
3. `Driving it with <harness>` 以 `Preconditions:` 开始，用带标签的列表，把每个用户动作配上确切命令和可观察结果。
4. `Gotchas` 列出会浪费或作废一次验证运行的陷阱。

实现细节不要放进地图。只点名用户路径、稳定句柄、必需状态、命令，以及可观察的证明。

## 功能

- [创建笔记](./create-note.md) 覆盖浏览器和 CLI 的创建、取消、持久化和清理。
- [搜索笔记](./search.md) 覆盖工具栏、键盘和 CLI 搜索，包括匹配、空结果和清空这几种状态。
