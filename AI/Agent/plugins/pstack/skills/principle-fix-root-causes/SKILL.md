# 修根因

调试时，修故障本身，而不是它露出来的地方。症状是错误状态变得看得见的地方。根因是系统第一次做了不该做的事，或者没处理它本该处理的状态。

**为什么：** 修症状会把证据藏起来，故障还能在别处再冒出来。每一次这样修，系统都更难推理，因为代码里多了一段没人命名的 bug 的权宜之计。

**做法：**
- 先复现。
- 每一步都问「为什么」，直到答案是代码里一个错误决定，而不是更早那个决定的后果。
- 卡住时就插桩。读真正的错误和真正的状态。不要猜。
- 问触发症状的那个状态是不是合法的。如果系统可以处于那个状态，在它上面崩掉的代码就是根因，在那里处理这个状态就是修复。如果这个状态本不该存在，在崩掉的地方加检查只会把 bug 藏起来。去找是什么产生了这个状态。守卫、重试、吞掉的错误、钳制的值、丢掉的状态，是藏 bug 的常见办法。
- 只有重启之后才失败时，先怀疑持久化状态：配置文件、缓存、锁文件、序列化状态。
- 查的是这个模式，不只是这一处。找到每一处同样的故障，全部修掉。
- 如果一段权宜之计需要一段话那么长的注释才能自圆其说，代码就是错的。改代码，不要改注释。
- 如果那个决定性的事实要深挖才找得到，就提出一个便宜、一直开着的信号，让它第一眼就能看见。
