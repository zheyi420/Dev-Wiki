# 控制适配器契约

Benny 不知道怎么启动或驱动每一个应用。用户必须配置一个控制 skill 或适配器，为目标应用实现这份契约。

把它的 skill 名设在 `control.skill_name`。

把填完的、面向用户的功能图路径设在 `control.feature_map_path`。把 [`feature-map.example.md`](./feature-map.example.md) 复制出来，在 `.cursor/automations/benny/` 之外填好，不要改复制来的例子。

skill、功能图或某项必需能力缺失、含糊或不完整时，复现和修复工作必须失败关闭。

## 必需能力

### 拉起

在请求的测试环境里启动请求的应用修订。

输入：

- 仓库和修订
- 构建或启动模式
- 工作区、账号、夹具和功能状态要求
- 产物目录
- 填完的功能图路径

返回：

- 会话标识
- 适配器如何确认应用和环境是对的
- 稳定的应用标记
- 后续调用需要的、正在运行的进程或目标细节
- 任何缺失的能力

适配器必须把目标应用和相似窗口、外壳或生产实例区分开。

### 驱动 UI

执行真实的用户动作：

- 点击
- 输入
- 按键
- 滚动
- 拖拽
- 调整大小
- 通过应用控件导航

优先用角色、标签和稳定选择器。只有刚截过图之后才用坐标。

返回每个动作，以及观察到的状态变化。

不要为了造出症状去设置内部状态、调用隐藏的应用方法、直接写存储，或注入 DOM 改动。

### 驱动映射的功能和状态

驱动应用之前，先读相关的功能图小节。

适配器必须提供这些办法：

- 沿着用户看得见的路径导航到每一个映射的功能。
- 调用这一功能列出的适配器动作名。
- 在适用时与默认、悬停、focus-visible、激活、禁用、加载中、空、错误、已选、打开、展开，以及功能特有的状态交互。
- 通过安全的夹具数据、权限、flag、服务响应或受支持的测试控件来布置状态。
- 为第二次独立的复现尝试重置这一功能。
- 采集功能图点名的截图、视频和只读交叉核对。

使用角色、无障碍名称、ARIA 关系、稳定的组件标记，以及按用途命名的 data 属性。绝不要用生成的 CSS 或 StyleX class、动态哈希、子节点序号，或脆弱的 DOM 位置。

布置前置条件不等于允许注入报告里的症状。复现本身仍必须来自真实的用户交互。

### 查看状态

读状态，确认 UI 显示的是什么。

例子：

- 无障碍树
- DOM 或视图层级
- 进程状态
- 本地日志
- 网络请求状态
- 应用暴露的调试状态

查看是只读的。如果一次查询会改状态，它就属于 `drive UI`，并且必须代表真实的用户动作。

### 截图

把当前应用状态采集到请求的路径。

返回：

- 文件路径
- 采集时间
- 应用标记或窗口标题
- 应该看见什么的简短描述

截图必须露出足够的应用外框，证明测的是正确的应用。

### 录屏

围绕完整复现路径开始并停止录屏。

返回：

- 文件路径
- 开始和停止时间
- 采集的窗口或区域
- 是否省略了音频或敏感浮层

录屏必须拍到能区分对错的最终状态，不能只拍准备过程或加载画面。

### 清理

停下适配器创建的进程和会话。

删掉一次性的：

- 浏览器或应用配置档
- 临时工作区
- 适配器创建的测试账号或夹具
- 调试端口和隧道
- 超过保留窗口的采集

返回停下了什么、删了什么、留了什么，或留给了人什么。

清理不得删掉用户的工作。

## 适配器行为

适配器必须：

- 复现开始前先报告能力。
- 报告它能驱动哪些功能图小节，哪些被阻塞。
- 基线构建和打过补丁的构建使用相同的环境输入。
- 启动失败就要报成失败。
- 限制重试次数。
- 密钥不要进日志和产物。
- 采集放在仓库外面。
- 两次复现尝试之间支持全新或重置后的状态。
- 不要改生产环境，除非用户明确配置了一个安全的测试动作。

## 环境转译

在宣布环境阻塞之前，先用不带平台专名的说法重述缺陷，再问同样的行为能不能在现有环境里安全地测。

例子：

- 点名的浏览器可能指任意外部浏览器。
- 点名的按键可能指配置好的快捷键。
- 点名的远程主机可能指延迟或断开的远程目标。

只有转译后的尝试测的是同一底层行为时才用它。把它标成转译证据。缺失的环境本身就是缺陷的一部分时，不要把它叫成精确复现。

硬件提示、操作系统权限对话框、仅设备可用的 API，以及不可用的账号状态，可以是真正的阻塞。

## 配置检查

启用复现自动化之前，跑一次无害的适配器检查：

1. 拉起应用。
2. 确认稳定的应用标记。
3. 加载一节填完的功能图。
4. 沿着用户路径导航到这一节对应的功能。
5. 通过映射的适配器动作演练一个一次性状态。
6. 查看得到的状态。
7. 截一张图。
8. 录一段短片。
9. 清理。

只有九步全部成功，并且没有来源频道的 Slack 发帖时，才启用复现工作。
